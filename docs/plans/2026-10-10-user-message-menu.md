# 用户消息入口迁回消息与公告

用户要求将 PC 管理员的“用户中心 / 用户消息”移回“平台运维管理 / 消息与公告”。

## 设计

- 复用 UserMessageManager，在用户沟通、公告管理之间恢复用户消息页签。
- 各页签按原有查询权限显示；只有用户消息查询权限时默认进入用户消息。
- 原发送、筛选、详情和收件人阅读情况保持可用。
- 移除旧侧栏入口，旧菜单及收藏地址跳转到 `/support/messages?tab=messages`。
- 迁移原角色的列表、发送和详情授权，补齐父目录和页面授权，不扩展公告或沟通权限。
- 新库和已有数据库统一执行 smartscript_full_init.sql，直接创建新入口或迁移旧菜单及其角色权限。

## 实施与验证

1. 修改组合页面和旧路由兼容逻辑，移除独立页面。
2. 更新初始化菜单种子，在初始化脚本第 10 部分内完成旧入口与权限迁移，不保留单独的增量脚本。
3. 验证旧路由、受限角色、迁移重复执行和消息数据保留。
4. 执行前端 lint、静态检查、测试和构建，在本机验证页面。

## 验证结果

- 前端 47 项测试、检查、构建与浏览器验证通过。
- 完整初始化脚本通过空库初始化、旧菜单权限迁移和重复执行验证。
- 消息、阅读记录、公告、原用户信息及自定义菜单授权保留。
- 新库结果：54 张表、2 个用户、3 个角色、194 个菜单、125 条角色菜单授权。
