A4 交付 PC 用户端个人资料、账号安全与公共布局：用户能够维护基本资料、查看账号及创作者信息、修改密码，并通过统一的身份判断、消息角标与会话处理使用个人工作台。

本文为开发规格，配套文档为验收依据。文中的“现有”仅表示 2026-09-30 静态代码核对发现已有实现，不代表功能已运行通过。“本次约定”是需要实现的目标行为；“建议契约”需要协作方落实后才能完成对应联调。本文不沿用已删除旧文档中的 A3/A4/A5 模块职责编号；源码里的历史编号注释不改变本次分工。

## 4 功能规格

### 4.1 页面结构

个人资料路由保持 `/pc/user/profile`，页面依次组织为基本资料、账号信息、创作者资料、账号安全、个人印章五个区域。未开通创作者能力的用户不展示创作者专属区；公共头像与昵称保存后立即同步。印章区域内部由 A5 组件渲染，加载与失败状态独立于基本资料。

资料首次加载期间使用骨架或遮罩，禁止提交空表单。加载失败显示“资料加载失败，请重试”和“重新加载”，不将失败当成无资料。账号基础资料为空或缺少必需身份字段时进入异常状态，不开放编辑；可选简介、头像、笔名等为空时正常显示默认内容。

### 4.2 基本资料与头像

- 昵称去首尾空白后必填，长度 1–30；简介去首尾空白，允许清空，最大 200。前后端使用同一长度口径，边界测试包括中文与表情，不在两端采用不同计数规则。
- 手机号只显示后端 `phoneMasked`，注册时间与账号状态只读；不通过资料保存接口修改用户编号、手机号、能力、角色、认证状态及账号状态。
- 头像支持 JPG/JPEG、PNG、GIF、BMP，大小不超过 5 × 1024 × 1024 字节。前端校验文件扩展名、类型与大小，后端仍独立校验；不因前端放行就视为安全图片。
- 选择文件后上传成功只更新待保存头像；点击“保存修改”后才绑定用户资料。上传失败保留原待保存头像，不发送资料保存请求。头像为空使用默认头像，图片加载失败有替代展示。
- 上传时禁用保存，保存时防止重复提交，并锁定会影响本次提交的输入；成功以服务端返回值更新表单和 Store，失败保留输入以便重试。
- “重置”恢复最近一次成功获取或保存的资料，不能将默认空值覆盖已保存内容。不得使用 `v-html` 渲染昵称、简介或创作者介绍。

### 4.3 账号信息与实名认证

注册时间来源为 `sys_user.create_time`，只读返回 `registeredAt`。本次约定输出 ISO 8601 带时区字符串，UI 转换为 Asia/Hong_Kong 的 `YYYY-MM-DD HH:mm:ss`；后端先明确数据库既有时间的时区配置，不能直接给无时区历史值拼接 `+08:00`。确实缺失的历史值返回 null 并显示“—”，新注册账号应有值。

账号状态复用 `sys_user.status`：`0` 正常、`1` 停用，未知值显示“状态未知”，不能兜底为正常。现有服务对停用用户拒绝返回资料，验收时通过禁用会话验证其失败处理，不能要求正常登录停用账号后读取完整资料。

实名状态展示：`NOT_SUBMITTED` 未认证、`PENDING` 审核中、`APPROVED` 已认证、`REJECTED` 未通过。未知值显示“状态未知”，避免错误显示已认证。返回字段不含身份证原文与证明材料内容。

### 4.4 创作者资料与入口控制

创作者能力唯一判断来源为 `/api/v1/auth/me` 返回的 `authorCapability === true`。`userType` 只用于账号类型文案；角色数组、实名通过以及 `userType === '02'` 都不能替代该能力判断。字段缺失或信息尚未加载时，不显示作品管理入口。

有能力用户展示“我的作品”及 A1/A2 作品页面入口，无能力用户隐藏入口；直接输入作品路由也需拦截，转工作台并提示“尚未开通创作者功能”。工作台中的作品快捷入口由 A1 按同一判断接入。后端作品接口必须独立判定身份与资源归属，A4 前端隐藏入口不能替代 A1/A2 的服务端校验。

创作者资料本次仅展示，不开放笔名和类型修改。展示笔名、擅长创作类型及介绍，未填写时显示“未填写”，类型列表为空时显示“暂未填写擅长类型”。保留账号昵称与笔名的区别。

当前核对的用户模块与全量 SQL 没有发现对应资料字段，本次建议由 A4 建立按 userId 一对一的只读投影 `creatorProfile`；确定项目资料来源后接入，禁止凭借作品记录或账号类型推断笔名。若必须新增存储，建议 `user_creator_profile`，含 `user_id` 唯一键、`pen_name`、`profile_intro`、类型代码数组及创建/更新时间，不与 `user_author_capability` 的能力开关混用。是否新建表、类型字典来源及合法代码需在开发步骤 D1 中落实并记录，禁止提交写死的演示资料作为真实用户资料。

**D1 决策（2026-09-30 记录）**：已按建议新建 `user_creator_profile`（见 `sql/smartscript_full_init.sql` 第 2 部分，`CREATE TABLE IF NOT EXISTS` 幂等），`specialties` 列以逗号分隔存储类型代码；后端按 `user_author_capability.enabled` 判定是否返回投影。类型字典来源：项目内无既有创作类型字典（`sys_work.genre_id` 指向内容模块的题材表，不在全量 SQL 管辖内），已在 `CreatorSpecialtyDictionary` 建立待登记映射——未登记代码的 `name` 回退为代码本身，不虚构名称；待内容模块确认后在该类登记，接口契约 `{code, name}` 不变。资料维护来源仍待项目协作确认，本次投影只读。

### 4.5 修改密码与退出

`hasPassword === true` 显示修改密码：旧密码、新密码、确认新密码。新密码 8–64 个字符（按 UTF-16 代码单元计）且至少包含字母和数字（按 Unicode 码点判断，与 `\p{L}`/`\p{Nd}` 同口径），并要求 UTF-8 编码不超过 72 字节（BCrypt 编码器输入上限，超限无法编码，返回明确参数错误而非 500）；保持现有后端 `validatePasswordPolicy` 的口径，以上规则前后端一致。新旧密码不能相同，确认新密码只作前端校验，不传给接口。密码不得 trim、缓存到本地或写入日志。

修改成功后后端现有逻辑吊销该用户全部会话；前端清空用户 Store、Access Token、Refresh Token 与账号类型，提示“密码已修改，请重新登录”并跳转登录页，不能再调用需要旧令牌的资料查询。

`hasPassword === false` 提供“设置密码”，复用 `/api/v1/auth/password/set`。该接口现有行为保留当前会话并吊销其他会话，成功后刷新 `/auth/me`。身份状态未知时先刷新，不要求无密码用户填写旧密码。状态冲突按服务端响应刷新入口。

退出登录调用既有端点；即使请求失败也清理本地用户会话、未读缓存与轮询，进入登录页。不得将退出失败提示写成仍然登录成功；管理员凭证域继续由既有账号切换机制处理。

### 4.6 会话与错误处理

- 游客访问工作台或资料页时跳登录页；有效用户登录后默认进入 `/pc/user/home`，合法且有权限的站内 redirect 可恢复，外部 URL 不可作为 redirect。
- 请求只携带 App 用户 Bearer Token；HTTP 401 或明确的认证失效业务码清理会话并跳转。现有认证业务码含 `40100`，不可只检测响应体 `code === 401`；普通业务错误不按令牌失效处理。
- 多个请求同时失效只触发一次跳转和一次失效提示；禁止循环请求、循环跳转。
- 已认证请求的普通 HTTP 403 显示权限或业务禁用提示，不一律当令牌过期。若账号停用明确返回对应业务码，清理其用户会话；普通网络超时、5xx、断网保持会话并允许重试。
- 首次 `/auth/me` 校验遇到临时网络故障显示重试状态，不仅因网络失败删除有效凭证；身份未确认期间不展示受保护内容。
- 不在本次引入静默刷新；当前令牌过期即重新登录。若未来更改策略，需单独更新契约及验收用例。

### 4.7 未读角标

菜单角标目标是沟通会话未读消息数与系统通知未读消息数之和，不是会话条数。系统通知已有 `GET /api/v1/messages/unread-count`，返回 `total` 与分类统计；它不代表聊天未读统计。

建议 A3 提供统一统计 `GET /api/v1/users/me/message-summary`，字段 `conversationUnread`、`notificationUnread`、`totalUnread`；这是拟定接口，尚未在本次核对中发现实现。若 A3 选择分接口，由 A4 在一个适配层合计，调用路径和字段须在 D1 中记录，不能把通知总数当全部消息数。

**D1 决策（2026-09-30 记录，缺陷 F03/F04 修复后更新）**：A3 统一统计未交付，前端已建立适配层 `src/stores/pcUnread.js`：`notificationUnread` 取既有 `GET /api/v1/messages/unread-count` 的 `total`；`complete` getter 在会话未读来源接入前恒为 false——合计不完整时不显示数字角标，仅有通知未读时显示圆点角标（附「有未读系统通知」说明），不把通知计数呈现为完整消息合计。A3 交付后在 `refresh()` 合并会话来源、按实际来源完整性计算 `complete` 并按已读事件刷新。轮询在 `PcUserLayout` 挂载时启动：初始立即查询、30 秒周期、请求重叠跳过、标签隐藏暂停、恢复可见即刷新、卸载与退出清理；`refresh()` 以 generation 代次作废在途请求，`reset()`（退出/换号）递增代次，旧响应不回写新会话状态（F04）。已读刷新挂接在消息页的单条已读与全部已读之后。

初始进入公共布局立即查询；已读、全部已读、发送/接收消息及返回消息页面后刷新。建议轮询间隔 30 秒，不重叠请求；标签隐藏暂停，恢复可见时刷新，退出或卸载停止。A3 提供刷新事件或共享状态，A4 只订阅与展示，不开发聊天轮询业务。

0 不显示角标；1–99 显示数字；超过 99 显示 `99+`。负值、NaN、字符串异常按失败处理。统计失败保留最后成功值，首次失败不伪造“0 条”；不反复弹出错误通知，恢复成功后纠正角标。两个来源部分失败时不能把不完整合计标为完整结果。

### 4.8 印章挂载与公共规范

建议挂载 `PersonalSealSection` 或 A5 提供的等价组件。A4 提供容器标题与布局；A5 自行从当前身份获取印章数据并提供内部加载、空态及错误状态。若必须传 userId，其值来自当前用户且后端仍检查归属。组件契约至少记录导出路径、是否需要属性、加载责任、是否发出刷新事件，完成后替换预留说明。

**D1 决策（2026-09-30 记录）**：A5 印章组件尚未交付。资料页已保留「个人印章」容器区域（标题 + 独立布局），占位显示「个人印章模块待接入」，不显示任何业务状态结论。待 A5 组件交付后：在 `src/views/pc/UserProfile.vue` 印章区域替换占位节点为 A5 组件；A5 需提供的契约信息包括导出路径、必需属性（如需 userId 由 `pcUserStore.user.userId` 传入）、数据加载责任方与刷新事件。

A4 不读取印章状态后决定显示哪个按钮，不计算印章是否能用于合同，不调用印章提交/重提接口。占位阶段显示“个人印章模块待接入”，不能显示“未申请”这种未经查询的业务结论。

沿用 Vue 3、Element Plus 与现有全局样式；将用户端共同样式限定在门户作用域。建议统一标题 22px、区域标题 16px、正文 14px、辅助信息 12px；间距使用 8/16/24/32px 梯度，主操作明确、危险操作使用语义色。输入须有可见标签，按钮有明确文案；键盘可完成表单与退出操作，错误不能仅靠颜色表达。

## 5 接口与字段契约

### 5.1 复用接口

| 方法与路径 | 用途 | 请求或响应关键点 |
| --- | --- | --- |
| GET `/api/v1/auth/me` | 身份信息 | `authorCapability`、`hasPassword`、现有用户字段 |
| GET `/api/v1/users/me/profile` | 读取资料 | 扩展下表中的资料字段 |
| PUT `/api/v1/users/me/profile` | 保存基本资料 | 只允许 `nickname`、`avatar`、`bio`；返回更新后的完整资料 |
| POST `/api/v1/users/me/avatar` | 上传头像 | multipart 字段 `file`；返回 `url`、`path` |
| POST `/api/v1/auth/password/change` | 修改密码 | `oldPassword`、`newPassword`；成功 data 可为空 |
| POST `/api/v1/auth/password/set` | 首次设置密码 | `password`；成功后刷新当前身份 |
| POST `/api/v1/auth/logout` | 退出 | 成功 data 可为空 |
| GET `/api/v1/messages/unread-count` | 系统通知未读 | `total`、`byType` |

成功响应沿用 `{ "code": 200, "message": "...", "data": ... }`，前端 `pcRequest` 返回 data。失败保留已有业务码与 HTTP 语义，不为了本文新增一套错误码。头像超限服务层现有返回 HTTP 413 / 业务码 41300。认证失效按现有 HTTP 状态与明确业务码识别。

### 5.2 资料响应增量扩展

| 字段 | 类型 | 来源及行为 | 实现状态 |

### 6.1.2 复验后 F07 二次修复记录（2026-09-30，依据 A4 复验报告（历史记录，本地留存））
