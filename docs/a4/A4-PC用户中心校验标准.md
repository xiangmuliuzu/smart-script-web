# A4 PC 用户中心校验标准

版本：1.0  
日期：2026-09-30  
适用范围：本次五人分工中的 A4 PC 用户端个人资料与公共功能。  
规格依据：[A4 PC 用户中心开发文档](A4-PC用户中心开发文档.md)

## 1 校验目标与结果口径

本标准将开发规格转换为可执行检查，覆盖资料、账号安全、创作者入口、会话、消息角标、印章挂载及公共体验。文档生成时未运行下列业务校验，所有用例初始状态为“未执行”；不得将已有代码、测试脚本存在或静态检查通过等同于功能验收通过。

结果统一使用：通过、失败、阻塞、未执行、不适用。不适用必须附理由并符合开发范围；A3 未交付、A5 未接入或创作者资料未有来源应记录为阻塞，不能记录为不适用或通过。

P0 为身份、越权、账号安全、核心资料持久化及必需字段等交付关键项；P1 为功能完整性、边界和异常体验；P2 为辅助视觉一致性。P0/P1 全部通过才可宣布 A4 整体完成；P2 缺陷如延期必须记录影响和处理计划，涉及可用性、数据或主流程则升级为 P1。

## 2 测试准备

在独立测试环境准备以下账号与资料，不使用真实身份证、真实手机号材料或生产口令。不同账号采用不同浏览器上下文或先完整退出，避免 Cookie/localStorage 串用。

| 夹具 | 条件 | 用途 |
| --- | --- | --- |
| U1 | 正常普通用户，`authorCapability=false`，有密码 | 基本资料及普通用户限制 |
| U2 | 正常用户，`authorCapability=true`，有笔名/类型/介绍 | 创作者展示和作品入口 |
| U3 | 有创作者能力，资料字段为空 | 空态 |
| U4 | 正常用户，`hasPassword=false` | 设置密码分流 |
| U5 | 第二个正常用户，资料与消息独立 | 数据隔离 |
| U6 | 可由测试管理员停用的用户，先持有效会话 | 停用后的拒绝与会话处理 |
| UA | 管理员，持管理端凭证 | 凭证域隔离 |
| 实名状态 | 未认证、审核中、已认证、未通过各一组 | 状态展示；可通过测试夹具/Mock 扩展 |
| 通知/聊天 | 分别有 0、1、99、100 条未读；聊天与通知都有未读 | 总数与显示边界 |
| 图片 | 合法各格式、5MB、5MB+1 字节、空文件、错误格式、损坏文件 | 上传边界与后端独立校验 |
| 会话故障 | 可控制过期令牌、无效令牌、403、5xx、超时、断网 | 错误分流 |

记录前后端代码版本、浏览器版本、测试时区、数据库结构版本及 A3/A5 组件版本。图片边界夹具应有效且可被上传组件接受；不能用 5MB 的随机二进制冒充合法图片来验证大小边界。

接口请求携带测试用户 `Authorization: Bearer <accessToken>`；密码、令牌、原始手机号在记录中脱敏。涉及身份变化的校验要以 `/api/v1/auth/me` 的实际响应为依据，不能只修改前端 Store。

## 5 密码与退出校验

| ID | 级别 | 操作或前置条件 | 预期结果 |
| --- | --- | --- | --- |
| A4-S01 | P0 | 有密码用户打开账号安全区 | 显示修改密码，不显示首次设置密码 |
| A4-S02 | P0 | 输入正确旧密码及合规新密码，确认一致 | 修改成功，当前用户会话清空，跳登录页；新密码可登录，旧密码不能登录 |
| A4-S03 | P0 | 修改前同时建立两个用户会话，修改后各访问受保护接口 | 两个旧 Access Token 和旧 Refresh Token 均不能继续认证或刷新 |
| A4-S04 | P1 | 旧密码错误 | 服务端拒绝，不改密码、不退出有效会话，可纠正后重试 |
| A4-S05 | P1 | 新密码 7/8/64/65 个 UTF-16 代码单元；纯字母、纯数字、字母数字组合；Unicode 字母（`\p{L}`，含汉字、补充平面字母）与十进制数字（`\p{Nd}`，含全角数字）交叉组合；UTF-8 编码 72/73 字节边界（如 `𠮷`×17+`ab12` 为 72 字节、`𠮷`×17+`abc12` 为 73 字节） | 合规口径：UTF-16 长度 8–64、至少一个 Unicode 字母与一个十进制数字（按完整码点判断）、UTF-8 编码不超过 72 字节（BCrypt 输入上限）；72 字节前后端均接受并完成改密，73 字节前后端均拒绝且为明确参数错误（不出现 500）；服务端独立执行同一策略，不静默截断 |
| A4-S06 | P1 | 新旧相同、两次新密码不一致、必填缺失 | 阻止错误提交；新旧相同绕过前端仍被服务端拒绝 |
| A4-S07 | P0 | U4 无密码账号打开安全区并设置合规密码 | 不要求旧密码；调用 set 端点，成功刷新 hasPassword |
| A4-S08 | P0 | U4 首次设置密码后检查当前与其他会话 | 当前会话按既有策略保留，其他会话吊销；不误用 change 成功后的退出策略 |
| A4-S09 | P1 | 密码提交超时/失败或状态冲突 | 没有虚假成功；状态冲突刷新身份入口；可重试，重复点击不发多次请求 |
| A4-S10 | P0 | 正常退出，再访问资料页或浏览器后退 | 令牌、账号类型、用户与未读缓存清空；轮询停止；受保护内容不能继续操作 |

## 10 自动化与构建检查

### 10.1 前端

在 `D:\build\smart-script-web-pc-user` 执行：

```powershell
npm run gate
```

通过条件：lint、静态检查、测试及生产构建全部退出码为 0。现有测试以静态与路由检查为主，不能代替浏览器交互与实际接口联调。按改动补充身份入口、密码分流、错误识别、未读统计及生命周期的有意义测试，不写仅验证代码文本存在的镜像测试来证明业务完成。

### 10.2 后端

在 `D:\build\smart-script-backend` 执行：

```powershell
mvn.cmd -pl smartscript-user -am test
mvn.cmd clean verify
```
