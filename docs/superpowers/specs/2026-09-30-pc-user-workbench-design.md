# PC 用户工作台设计

## 目标与范围

登录成功后，账号类型 `01/02/03` 进入独立的 PC 用户工作台。页面沿用管理端的深色侧栏、顶部导航和浅色内容区。管理员仍使用服务端动态菜单。

本次采用已确认的“页面框架 + 现有接口”范围：工作台首页、我的作品五个状态入口、消息与沟通、个人资料。作品列表暂不请求管理端接口，也不展示模拟作品；用户侧按本人筛选的作品接口和“待修改”状态契约明确后再接入。

## 路由和页面

`/pc/user` 重定向至 `/pc/user/home`。共用 `PcUserLayout` 提供侧栏、面包屑、账号信息和退出登录。作品入口分别为 `/pc/user/works/{all,draft,review,revision,listed}`，页面显示状态导航与明确的接入提示。`/pc/user/messages` 承载站内消息；`/pc/user/profile` 承载个人资料。

## 数据流

所有用户业务请求走现有 `pcRequest`，携带 App 凭证域令牌。消息页使用 `/api/v1/messages` 列表、详情、单条已读和全部已读接口，支持类型筛选、分页及加载失败重试。资料页使用 `/api/v1/users/me/profile` 查询和更新昵称、头像、简介，并通过 `/api/v1/users/me/avatar` 上传头像。保存成功后同步 `pcUser` store 的展示信息。手机号、账号类型、实名状态只读。

## 验证

运行 Web 项目的 `npm run gate`；在浏览器中用模拟接口检查用户首页、侧栏导航、消息详情和个人资料的渲染与无运行时错误。后续作品接口接入需要独立验证身份隔离及状态映射。
