# 消息功能细节调整

用户明确要求删除消息与公告中的用户消息页签、详情即已读并由打开者处理、仅结束/重新打开两种状态操作，以及修复 App 消息页面的白色背景。

1. 消息与公告保留用户沟通及公告管理页签，默认进入用户沟通。现有独立消息发送接口和历史通知继续兼容。
2. 详情先加载会话和消息，再通过管理域的显式打开接口，将当前管理员记录为处理人，并将已显示的用户消息标为已读。权限沿用详情/消息查询权限，不要求人工分配权限。
3. 打开动作只在进入详情时执行。前台轮询可将新显示的消息标为已读，不能重新抢占其他管理员已经打开的会话。读取只覆盖显示消息的最大编号，后到而未展示的消息保持未读。
4. 处理人使用 assigned_admin_id，保留原始 user2_id 作为会话业务唯一键的一部分。用户消息投递和对方信息使用当前处理人，避免更换处理人导致会话合并或唯一键冲突。历史发给之前管理员的用户消息也能正确已读。
5. 界面只呈现进行中、已结束；历史状态 1 兼容为进行中，状态筛选涵盖历史 0/1。结束保存 2，重新打开保存 0。移除处理中操作。
6. App 筛选条和消息行移除硬编码白色底，沿用应用全局背景，保持原有分类、分页及点击范围。
7. 验证自动已读、不同管理员打开接手、轮询不接手、显示范围之外的消息保持未读、结束与重开和旧状态兼容；在本机更新后端并覆盖安装模拟器 App，保留现有登录和数据。

直接按已明确的用户要求实施，改动保留待审核，不提交或推送。
