# 头像上传修复

用户已确认修复 2026-10-09 检查报告中的四项问题。范围为现有头像上传、资料保存和 App/PC 头像展示，不新增依赖、不调整数据库列、不变更云端。

## 数据与地址

后端继续返回 url/path 以兼容现有上传响应。新客户端优先保存 path，后端允许安全的 /profile/upload/ 和 /profile/avatar/ 资源路径，并把历史上传绝对地址规范为资源路径；外部 HTTP(S) 图片地址保持兼容。地址规范化后仍受 sys_user.avatar 的 100 字符限制。前端统一资源地址转换，保留当前 API 的网关前缀，App 去除 /api/v1 后拼接资源路径；PC 沿用 API 代理前缀。历史含 localhost 或 10.0.2.2 的平台头像也按当前后端地址显示。

## 上传与选择

后端用 ImageIO 校验实际格式、像素和完整内容，允许 JPEG/PNG/GIF/BMP，按识别结果生成扩展名，再用已有 FileUploadUtils 的 UUID 命名。原文件扩展名仍须属于支持列表，避免不支持文件绕过规则。Android 保留正确扩展名，原生后台复制过程中限制 5 MiB，空文件、超限和复制失败均清理缓存；Dart 读取前也检查大小。取消选择返回 null，禁止上传和保存并发，离开页面后不再发起上传。

## 验证

后端覆盖 UUID 短路径、长原名、格式纠正、资源路径校验、历史绝对地址规范化及现有安全限制；Web/App 覆盖历史地址与不同网关前缀解析、选图取消、超限缓存清理和上传响应。使用临时账号验证 PC 实际页面与 Flutter 仓库上传保存、模拟器资源访问；清理测试账号和文件。更新模拟器 App 并保留其登录和用户资料。
